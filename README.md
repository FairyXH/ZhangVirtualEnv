# ZhangVirtualEnv

ZhangVirtualEnv 是面向 Android 应用开发的系统环境参数测试与兼容性验证框架。它通过可控的测试配置、系统 API 测试适配和本地控制接口，为开发调试、自动化测试、回归测试和多版本兼容性验证提供可重复的 Android 测试环境。

项目只面向由使用者控制或已获授权的测试设备和测试对象，不针对任何特定应用、第三方服务或线上业务提供适配。

## 主要能力

- Location API 单点与轨迹测试，支持更新频率、连续回放和位置状态观察；
- GNSS API 测试，包括卫星状态、NMEA 数据、回调时序和位置更新链路；
- 远程环境测试支持通用 Collector/Consumer API 的 GPS、GNSS 和 Sensor 数据，并保留每种数据的时间戳、序列号和扩展字段；
- GPS 远程数据支持静态定位点和多点轨迹：静态点用于单点测试，多点数据由系统位置引擎按服务端速度参数进行轨迹回放；
- CellInfo 与 Telephony API 测试，覆盖常见网络制式、订阅状态和信号摘要字段；
- Wi-Fi 扫描结果测试，支持网络标识、信号和频率等结构化字段；
- Bluetooth/BLE 扫描结果测试，支持 BLE 广播摘要、经典发现和原始字段保存；
- 传感器事件流测试，支持步频、累计值、时间戳和连续事件回放；
- 测试环境采集、快照、录制、回放、预设、JSON 导入导出；
- 本地 API、调试状态、测试报告和诊断包，便于脚本与 CI 集成；
- 远程信息采集数据接入，支持最新数据快照、连接状态、数据新鲜度和断线恢复；
- 按设备能力选择测试后端，异常时恢复系统原始行为。

## 设计原则

- **数据驱动**：将测试参数组织为 Profile 或测试数据包，便于复现和跨设备复用；
- **控制与适配分离**：控制端负责配置和状态展示，核心服务负责状态与数据，适配层负责标准 Android API 的测试数据呈现；
- **最小测试范围**：只处理测试所需的系统框架和必要系统组件，不面向具体第三方应用建立适配；
- **可观测**：每个测试项提供启用状态、后端状态、更新时间、失败原因和报告摘要；
- **fail-open**：测试配置缺失、版本不匹配或适配失败时保留系统默认行为，避免影响设备稳定性；
- **可恢复**：测试项可以独立启停，测试结束后可清理配置并恢复默认数据面。

## 系统架构

```text
┌──────────────────────────────┐
│ 控制端 App                    │
│ Profile、位置、轨迹、环境配置 │
│ 录制回放、报告和设置           │
└──────────────┬───────────────┘
               │ 本地受保护 API
┌──────────────▼───────────────┐
│ Backend Core                  │
│ 测试状态、数据引擎、快照、回放 │
│ 持久化、诊断与远程数据归一化   │
└──────────────┬───────────────┘
               │ 周期读取或事件分发
┌──────────────▼───────────────┐
│ Android API 测试适配层         │
│ Location / Telephony / GNSS   │
│ Wi-Fi / Bluetooth / Sensor    │
└──────────────┬───────────────┘
               │
┌──────────────▼───────────────┐
│ 受测应用                      │

└──────────────────────────────┘
```

系统级测试适配由版本 Profile 和能力检测共同决定。传感器等连续数据支持多级后端和自动回退；任何后端未通过版本或特征校验时，不应阻断系统原始数据链路。

## 测试数据

测试配置按功能项独立组织，可分别启用或暂停：

- 位置：坐标、轨迹点、回放速度、时间戳和更新频率；
- GNSS：卫星状态摘要、星座、信号参数、NMEA 和回调序列；
- 蜂窝网络：网络制式、小区标识和可公开读取的 Telephony 字段；
- Wi-Fi：SSID/BSSID 等测试标识、信号强度、频率和扫描结果；
- Bluetooth/BLE：设备标识、广播字段、服务数据、RSSI 和时间戳；
- 传感器：类型、步频、累计值、事件时间戳和连续样本；
- 订阅信息：测试设备上可读取的订阅和网络状态摘要。

项目提供字段范围校验、样例配置生成、测试配置预设和 `.vrenv.json` 测试数据包。真实设备标识、位置、认证值和采集数据不应写入公开仓库或 README 示例。

## 环境要求

- Android 10 或更高版本；
- 具备系统级测试能力的已授权测试设备；
- Root、系统测试加载器或其他系统集成条件应按目标设备和测试实验室要求准备；
- 如需远程测试数据，需要可访问的物联网信息采集服务端和有效的测试凭据；
- 地图或外部数据源属于可选测试准备能力，不是核心运行依赖。

## 构建与安装

```bash
cd ZhangVirtualEnv
./gradlew assembleDebug --no-daemon

adb install -r app/build/outputs/apk/debug/app-debug.apk
```

独立校验工具可单独构建：

```bash
cd ../VirEnvDetector
./gradlew assembleDebug --no-daemon
```

Windows PowerShell 构建示例：

```powershell
.\gradlew.bat assembleDebug --console=plain --no-daemon > build.log 2>&1
Get-Content build.log -Tail 80
```

系统级测试组件安装或更新后，应按目标设备要求重新加载测试环境。涉及重启的验证必须先保存测试配置和日志，并在测试窗口内执行。

## 基本使用流程

1. 在授权测试设备上安装并启动控制端；
2. 配置一个单项测试或导入固定 Profile；
3. 启用所需测试项，确认控制端显示运行状态和最近更新时间；
4. 启动目标 Android 测试应用，执行对应功能用例；
5. 使用控制端状态、独立校验工具、测试报告和系统日志交叉确认结果；
6. 逐项测试进程重启、Activity 重建、权限变化、远程断线和配置切换；
7. 停用测试项、清理临时数据并确认系统 API 恢复到预期默认行为。

### 自动化测试

所有核心操作通过本地测试 API 完成，可由脚本或 CI 驱动：

- 加载固定测试配置；
- 启用或暂停单个测试项；
- 启动、暂停、继续和停止录制或回放；
- 读取测试状态和后端状态；
- 导入导出测试配置；
- 提交、读取和归档测试报告。

自动化断言应同时记录设备 API 级别、系统版本、配置版本、测试项状态、数据时间戳和日志摘要。

## 本地 API

默认本地地址为 `127.0.0.1:18790`，请求需要测试环境约定的认证头。公开文档只列出稳定的接口类别；认证值、内部路径和设备专用配置应通过本地安全配置注入。

| 方法 | 路径类别 | 用途 |
| --- | --- | --- |
| `GET` | `/api/status`、`/api/system/info` | 服务、模块和系统摘要 |
| `GET/POST` | `/api/location/*`、`/api/route/*` | 位置和轨迹测试数据 |
| `GET/POST` | `/api/env/*` | 各环境测试项状态、配置和生命周期 |
| `POST` | `/api/env-snapshot/*`、`/api/env/use` | 快照创建、列表、删除和应用 |
| `POST` | `/api/recording/*` | 录制和回放控制 |
| `GET/POST` | `/api/preset/*`、`/api/config/*` | 测试预设与配置导入导出 |
| `GET/POST` | `/api/test/report` | 测试结果提交和查询 |
| `GET` | `/api/remote/status` | 远程测试会话和归一化快照状态 |

各接口的请求字段应以当前版本的服务端实现和测试契约为准。未授权或格式错误的请求应记录为测试基础设施问题。

## 远程信息采集

框架可连接受控的物联网信息采集服务端，接收结构化的环境数据快照。远程连接由常驻协调组件维护，页面只展示连接和测试状态；系统 API 测试适配层只读取已归一化的本地快照，不直接解析远程协议。

远程链路包含：连接建立、心跳、设备选择、订阅、最新帧缓存、数据新鲜度检查、序号确认、断线重连和本地回退。连接异常时应保持 fail-open，并在报告中区分“无数据”“数据过期”“认证失败”和“本地适配失败”。

## 兼容性与设备适配

项目以 Android 10+ 为基础目标，并按 API 级别、系统服务实现、权限模型、回调时序和厂商差异逐项验证。已验证的版本必须在发布记录中标明设备类型、Android API 级别、系统版本、测试项和验证日期；仅完成静态分析或构建的版本不得标记为真机支持。

新设备适配建议按以下顺序执行：

1. 记录系统版本、API 级别、架构和可用权限；
2. 逐项确认 Android 类、方法签名、字段和回调时序；
3. 为新增差异建立独立 Profile，不扩大已验证配置边界；
4. 先执行单项测试，再执行组合测试和长时间回放；
5. 验证异常、进程重启、服务重启和后端回退路径；
6. 由独立校验工具、日志和测试报告共同确认结果。

未匹配的版本 Profile、缺少能力或系统服务异常时，测试适配应跳过或回退到系统原始行为。
