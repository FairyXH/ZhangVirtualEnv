# 目标类分析：Location 链路（Phase 1）

> 分析材料：`D:\Files\Develop\Android\ZhangVirtualProject\JadxAnalyse\framework\services.jar`（ColorOS/Android 15 环境，经 JADX 反编译）
> 本文仅覆盖 Phase 1 所需的 Location 相关类，其余类（Wifi/Cell/BLE/Sensor/GNSS）后续 Phase 再分析。

## 1. LocationManagerService

### 类路径

`com.android.server.location.LocationManagerService`

### 关键方法签名

| 方法 | 签名 | Hook 用途 |
|---|---|---|
| getLastLocation | `Location getLastLocation(String packageName, LastLocationRequest request, String attributionTag, String featureId)` | Phase 1 核心：应用调用 `LocationManager.getLastLocation()` 时最终到达此处 |
| getCurrentLocation | `ICancellationSignal getCurrentLocation(String packageName, LocationRequest request, ILocationCallback callback, String attributionTag, String featureId)` | 后续 Phase：应用 `getCurrentLocation()` 异步回调 |
| registerLocationListener | `void registerLocationListener(String packageName, LocationRequest request, ILocationListener listener, String attributionTag, String featureId)` | 后续 Phase：连续位置更新 |
| injectLocation | `void injectLocation(Location location)` | 辅助：向系统注入位置 |
| setTestProviderLocation | `void setTestProviderLocation(String provider, Location location, String packageName, String attributionTag)` | 辅助：测试 provider |

### Hook 点结论（Phase 1）

- **主入口**：`getLastLocation`。before 阶段替换返回值，可覆盖绝大多数"单次获取最后位置"场景（地图 App、微信等）。
- **注意**：`getLastLocation` 返回值是 `android.location.Location`，直接返回虚拟对象即可，无需调 `chain.proceed()`（但为了兼容，失败时必须放行原始逻辑）。

## 2. GnssLocationProvider

### 类路径

`com.android.server.location.gnss.GnssLocationProvider`

### 关键方法签名

| 方法 | 签名 | Hook 用途 |
|---|---|---|
| onReportLocation | `void onReportLocation(boolean hasLatLong, Location location)` | Phase 1 核心：GNSS HAL 上报真实位置到框架 |
| onReportLocations | `void onReportLocations(Location[] locations)` | 后续 Phase：批量位置上报 |
| injectBestLocation | `void injectBestLocation(Location location)` | 后续 Phase：注入最佳位置 |

### Hook 点结论（Phase 1）

- **主入口**：`onReportLocation`。在真实 GNSS 上报时把 `location` 参数替换为虚拟位置，框架继续走正常分发链路（LocationManagerService → 各 App listener）。
- **优势**：不破坏注册监听链路，对 `requestLocationUpdates` 类应用天然生效。
- **风险**：`onReportLocation` 仅在真实 GNSS 有信号时被调用；室内无 GNSS 信号时不会触发。Phase 1 以 `getLastLocation` 为主、`onReportLocation` 为辅。

## 3. Google Play Services（FusedLocationProvider）

### 材料

`Google Play 服务_26.29.32 (260400-956293556).apks` → `base.apk`（主包，190MB）

### 现状

- GMS 主包为 APKS 多分片格式，`base.apk` 内含 FusedLocationProvider 相关代码。
- **Phase 1 暂不深入反编译 GMS**，仅记录位置。
- 后续 Phase 目标：`com.google.android.gms.location.internal.FusedLocationProviderImpl` 或内部 provider 回调，确认精确类名后再写 Adapter。

## 4. 调用流程（Phase 1 关注的路径）

```
App (LocationManager.getLastLocation)
  → Binder → LocationManagerService.getLastLocation(...)   [Hook A]
      → 返回 Location

App (LocationManager.requestLocationUpdates)
  → LocationManagerService.registerLocationListener(...)
      → GnssLocationProvider.onReportLocation(hasLatLong, location)  [Hook B]
          → LocationManagerService 分发 → App listener
```

## 5. Android 版本差异（已知）

| 版本 | 差异点 |
|---|---|
| Android 12 (S) | `getLastLocation` 签名含 `LastLocationRequest` |
| Android 13 (Tiramisu) | 引入 `GnssLocationProvider` 拆分到 `com.android.server.location.gnss` |
| Android 14 (U) | 基本同上，`LocationManagerService` 构造含 `Injector` |
| Android 15 (V) | 当前材料（ColorOS 15），签名与 14 基本一致，含 Oplus 扩展方法 `oplusSystemReady` |

> Profile 文件用于承载这些差异：`profiles/android14.json`、`profiles/android15.json`、`default.json`。
> Hook Adapter 通过 Profile 决定启用哪些方法，不硬编码 Android 版本类名。
